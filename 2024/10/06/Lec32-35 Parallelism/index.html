Flynn’s Taxonomy

  • 软件的并行性与硬件的并行性相互独立——并行软件可以运行在串行硬件上，反之亦然。Flynn 分类法是对硬件的分类，按指令流和数据流分为四类：
  1. SISD：单指令流单数据流。传统串行计算机，CPU 逐条执行指令，每次处理一个数据项。
  2. SIMD：单指令流多数据流。同一指令同时对多个数据元素操作，适用于图形处理、科学计算。例如 GPU 和向量处理器。
  3. MISD：多指令流单数据流。多个处理单元对同一数据执行不同指令。较罕见，主要用于容错系统。
  4. MIMD：多指令流多数据流。多处理器独立执行不同指令处理不同数据。现代多核 CPU、分布式系统属于此类。通常由多个 SIMD 组成。

SIMD Architecture

  • 通常通过将数据放在更宽的寄存器中实现，例如 x86 的 SSE/AVX 指令集利用 128/256/512 位寄存器一次操作多个数据元素。

Thread-Level Parallelism

  • 线程级并行是一种软件并行。多核 CPU 意味着每个核都有独立的完整数据通路和指令流，不同核可同时执行不同线程。

Thread

  • 硬件线程：由处理器核心直接支持的线程，每个核心可拥有一或多个硬件线程。
  • 软件线程：由程序代码创建和管理的线程，运行在操作系统中，通过调度机制管理其生命周期。单核 CPU 运行多线程的方式是时间共享（时分复用）。

Multithreading

  • Hyper-Threading（超线程）：每个支持超线程的物理核心对外表现为两个逻辑核心，可以同时执行两个线程。当一个线程因等待数据（如缓存缺失）而停顿时，另一个线程可以继续执行，提高核心利用率。

OpenMP

  • OpenMP 是一种用于共享内存多处理编程的 API。通过 #pragma omp parallel for 等指令并行化循环：
  • 创建的子线程是乱序执行的。OpenMP 将循环迭代分配给线程池中的各线程，每个线程独立执行分配的迭代，线程间通过共享内存通信。在 #pragma omp parallel 区域中，若多个线程同时访问共享资源并读写，可能产生竞争条件——读到旧值后写回基于旧值计算的新值，导致数据错误。

Hardware Synchronization

  • 软件层面使用锁（mutex）或信号量防止共享资源被多线程同时访问。
  • 硬件层面通过原子操作实现：在一条指令内完成”读-修改-写”，中间不能被其他处理器打断。例如 RISC-V 的 lr/sc（Load-Reserved / Store-Conditional）指令对。
  • 死锁：两个或多个线程因争夺资源而相互等待，导致都无法继续执行。

Shared Memory and Caches

  • 每个处理器核心拥有自己的私有 L1/L2 缓存，所有核心共享主存。这导致缓存一致性问题：一个核心修改了某地址的数据，其他核心的缓存中该地址的副本就过期了。

Cache Coherency

  • 缓存一致性是在多处理器系统中保持各私有缓存数据一致的机制。常用实现为 Snoopy 协议：
    • 每个缓存控制器”监听”总线上的读写操作。
    • 当一个处理器写入数据时，广播失效消息（或更新消息），其他缓存将对应行标记为无效（invalidate）或更新为新值。
    • 常见一致性状态（MSI 协议）：
      • Modified：该缓存行被修改过，且只在当前缓存中有效。写回前主存中的副本已过时。
      • Shared：该缓存行可能存在于多个缓存中，与主存一致。只读。
      • Invalid：该缓存行无效，不可用。
  • 一致性缺失（Coherence Miss）：因缓存一致性协议导致两个核心交替写入同一缓存行，数据在彼此缓存间来回传递，增加延迟。可通过减小块大小缓解（但块太小又会影响空间局部性）。
