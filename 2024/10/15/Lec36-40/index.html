MapReduce & Spark

Amdahl’s Law

Request-Level Parallelism

  • 请求级并行（RLP）是一种并行计算模型，多个独立请求同时被处理，彼此无依赖关系。典型场景是 Web 服务器同时处理多个 HTTP 请求，每个请求各自独立。

MapReduce

  • MapReduce 框架将大数据处理分为两个阶段：
    • Map 阶段：输入数据分割为多个小块，并行执行用户定义的 Map 函数，将输入转换为一组键值对。例如单词计数中将 “I do I learn” 映射为 (“I”,1), (“do”,1), (“I”,1), (“learn”,1)。
    • Reduce 阶段：按键分组所有 Map 输出的键值对，对每组执行 Reduce 函数生成最终结果。例如对 (“I”,1) 和 (“I”,1) 的 reduce（求和）得到 (“I”,2)。
  • 中间的 Shuffle 阶段负责将 Map 的输出按键分发到对应的 Reducer。

Spark

  • Apache Spark 是一个开源的大数据处理框架。关键创新是将在内存中处理中间数据，而非像 Hadoop MapReduce 那样每次 Map-Reduce 迭代都写入磁盘。这使迭代算法（如机器学习训练）的速度有数量级的提升。

Dependability

  • 通过冗余组件减轻硬件故障：
    • 空间冗余：备份磁盘/RAID 阵列，多个副本存储相同数据。
    • 时间冗余：发生暂时故障时重复执行操作，有可能成功。
  • 软错误：硬件本身无故障，由于环境干扰（宇宙射线、电磁干扰）导致数据位翻转。
  • 硬错误：硬件物理损坏或永久性故障。

GPU Guest Lecture

  • GPU 架构与 CPU 的设计哲学完全不同。CPU 核心少但每个核心复杂（大缓存、分支预测、乱序执行），适合低延迟的串行任务。GPU 拥有数千个简单核心，设计为海量线程并行执行——当某些线程等待访存时，硬件调度器立即切换到其他已就绪的线程，通过这种细粒度多线程隐藏访存延迟。
  • GPU 工作模式：CPU 将数据和内核代码加载到 GPU 显存 → GPU 启动海量线程并行处理 → 完成后由 CPU 读取结果。GPU 并不擅长处理小块的工作，造成这种情况的原因是在设置和启动 GPU 方面存在大量的开销
