Binary Prefix

  • 二进制前缀（KiB, MiB, GiB 等）基于 2 的幂次，而十进制前缀（KB, MB, GB）基于 10 的幂次。1 KiB = 1024 字节，1 KB = 1000 字节。网络传输和硬盘容量通常使用十进制，内存和其他领域一般使用二进制。

Memory Hierarchy

  • 由于 CPU 和内存的速度差距巨大（访问一次 DRAM 的延迟大约为几百个周期），引入缓存（cache）作为临时存储数据的快速区域。缓存是主存部分数据的副本，比内存小得多但快得多。典型的层次为：寄存器 → L1 Cache → L2 Cache → L3 Cache → 主存 → 磁盘。

Locality, Design, Management

  • 缓存的工作原理依赖两种局部性：
    • 时间局部性：刚使用过的数据很快可能被再次使用。
    • 空间局部性：访问内存不是完全随机的，访问某个地址后很可能很快访问其邻近地址。

Direct-Mapped Cache

  • 直接映射缓存将每个内存地址映射到缓存中的固定位置。内存地址被划分为三个字段：

    Tag（标签） | Index（索引） | Block Offset（块内偏移）

    • Index 确定该地址映射到缓存的哪一行
    • Tag 存储在缓存行中，用于判断该行是否确实包含所需数据
    • Block Offset 在缓存行内定位具体字节
    • 每个缓存行还包括一个 Valid 位，标识该行数据是否有效

  • 当 CPU 发出内存访问时，用地址的 Index 找到缓存行，比较 Tag 并检查 Valid 位。若匹配且 Valid=1，则为命中（hit）；否则为缺失（miss），需要从主存加载整个块到缓存。

Writes, Block, Sizes, Misses

  • 写操作时有两种策略：
    1. 写直达（Write-Through）：同时写入缓存和主存，保持一致性但慢。
    2. 写回（Write-Back）：只更新缓存，被替换时才写回主存。需要一个 Dirty 位标记缓存行是否被修改过。
  • 块大小的权衡：块太小会损失空间局部性（无法利用邻近数据），块太大会损失时间局部性（每个块占用更多缓存空间，替换频率增加）。
  • 缺失的三种类型：
    • 冷启动未命中（Compulsory Miss）：首次访问，缓存为空。
    • 容量未命中（Capacity Miss）：缓存空间不足以容纳所有活跃数据。
    • 冲突未命中（Conflict Miss）：多个地址映射到同一缓存位置，互相踢出。

Fully Associative Cache

  • 全相联缓存允许任意内存地址映射到缓存的任意行。不再有 Index 字段，整个地址的 Tag 直接与所有缓存行并行比较。没有冲突未命中，但硬件复杂度和功耗更高，仅适用于小型缓存（如 TLB）。

组相联缓存

  • 介于直接映射和全相联之间：缓存分多个组（set），每组内有 N 路（N-way），地址先映射到固定组，然后在组内可存放于任意一路。兼具较低冲突未命中和较低硬件开销。典型实现为 4 路或 8 路组相联。

块替换

  • 直接映射：只能踢出唯一映射位置。
  • 全相联和组相联：在组内进行替换，常见策略：
    • LRU（最近最少使用）：需维护访问次序，硬件开销较大。
    • FIFO（先进先出）。
    • 随机替换：简单且效果通常接近 LRU。

平均内存访问时间：AMAT


  • 更大的块意味着更低的缺失率但更高的缺失代价（加载更多数据），二者需要平衡。通过添加 L2、L3 缓存，可以在减小缺失率的同时控制缺失代价。
