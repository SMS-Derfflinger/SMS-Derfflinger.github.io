Operating Systems Basic

  • 硬件只能完成特定功能，复杂任务需要编程软件实现。最重要的系统软件就是操作系统。
  • 操作系统使计算机可以同时运行多个程序，为每个进程提供独立的虚拟地址空间，并通过页表将虚拟地址映射到物理地址。这种映射功能由硬件提供支持。
  • 不同用户权限对应的 CPU 模式：用户模式（U-mode）、管理模式（S-mode）、机器模式（M-mode），通过控制和状态寄存器（CSR）切换。
  • 计算机启动过程：上电后从 ROM 加载固件/BIOS → 加载 bootloader → bootloader 加载操作系统内核 → 内核初始化后将控制权交给用户态程序。

Operating Systems Functions

  • 中断：由外部事件引起（如键盘输入），独立于当前运行程序，不必立即处理。
  • 异常：由程序内部引起（如除零、缺页），通常是严重错误，必须立即处理。
  • 两者处理方式类似，都通过 trap handling 机制：保存当前寄存器状态 → 跳转到 trap handler → 处理后恢复状态返回。操作系统通过上下文切换实现大量程序的”同时”运行。

Virtual Memory

  • 虚拟内存让每个运行的程序以为它拥有非常大的连续内存空间。它实现了三个关键功能：
    • 隔离性：各进程的地址空间彼此独立，互不影响。
    • 内存共享：多个进程可以共享部分物理内存（如共享库）。
    • 磁盘扩展：将不常用的内存页换出到磁盘，释放物理内存。

Physical Memory and Storage

Memory

DRAM（动态随机存取存储器）

  • 用作计算机的主内存（RAM），存储密度高、成本低。
  • 数据存储在电容器中，需要定期刷新以保持数据。

SRAM（静态随机存取存储器）

  • 用作 CPU 缓存（L1/L2/L3），速度快但密度低、成本高。
  • 数据存储在触发器中，无需刷新，断电丢失。

Storage

SSD（固态硬盘）

  • 使用 NAND 闪存存储数据，以块为单位擦除和写入。速度快、无移动部件、功耗低。

HDD（机械硬盘）

  • 使用磁性盘片和机械臂读写数据。容量大、成本低，但访问时间长、易受物理损坏。

Memory Manager

  • 内存管理器负责：分配和回收内存空间；管理虚拟地址到物理地址的映射；处理缺页异常；在内存不足时将页面换出到磁盘并换回所需页面。

Paged Memory

  • 分页内存将物理内存和虚拟内存划分为固定大小的块（页/页框）。当程序访问虚拟地址时，页表将虚拟地址转换为物理地址。
  • 虚拟地址连续的页面，在物理内存中可以不连续。这种不连续分配使得物理内存的利用率更高，减少外部碎片。
  • 页表通常存储在主存（RAM）中，因为页表大小对缓存来说太大了。可将页表中被经常访问的条目缓存在 TLB 中以加速转换。

Page Faults

  • 缺页（Page Fault）发生在程序访问的虚拟地址不在物理内存中时——可能对应的物理页在磁盘中，或者从未被访问过需要首次分配。此时操作系统从磁盘加载页面，更新页表，然后重新执行出错的指令。

Hierarchical Page Tables

  • 32 位系统中，页大小通常为 4KB，页面数为 ，单级页表大小为 4MB。若支持 256 个进程，页表总开销为 1GB。在 64 位系统中这个问题更加严重。
  • 层级页表将页表分为多级：一级页表指向二级页表，最终指向物理页面。只有实际使用的地址范围才分配对应的下级页表，大幅节省内存。例如 SV39 采用三级页表，每级 9 位索引，逐级查找最终得到 4KB 物理页地址。

Translation Lookaside Buffers

  • 层级页表增加了内存访问次数（每次地址转换可能需多次查表），需要硬件加速。TLB（Translation Lookaside Buffer）是缓存最近被访问的页表项的小型快速缓存，访问 TLB 大约在一个周期内完成。
  • 替换策略通常为 FIFO、LRU 或 Random。
  • TLB 的访问先于缓存——缓存中存储的是物理地址标签而非虚拟地址。TLB 位于数据通路中缓存之前，地址转换流程为：虚拟地址 → TLB 查找 → 物理地址 → 缓存查找 → 命中则返回数据，未命中则访问主存。
  • 绝大多数情况下 TLB 都会命中。少数未命中时需要多次访问内存加载多级页表项，开销较大。上下文切换时需要刷新 TLB（因为地址空间变了），除非 TLB 支持地址空间标识符（ASID）。

IO Devices

  • 计算机通过统一的 IO 接口与外部设备交互。可通过内存映射 IO（MMIO）实现：为每个 IO 设备分配一段不与主存冲突的地址范围，CPU 用普通访存指令读写设备寄存器。

IO Polling

  • IO 轮询：CPU 定期检查 IO 设备的状态寄存器，判断是否需要服务。实现简单但效率低——即使设备空闲，CPU 也在浪费时间循环检查。

IO Interrupts

  • 中断驱动 IO：设备在需要 CPU 处理时主动发出中断信号。CPU 暂停当前任务，执行中断处理程序后恢复。适用于速度不高的设备（键盘、鼠标），避免了空转等待。

DMA

  • 直接内存访问（DMA）：允许外部设备直接与主存交互数据，无需通过 CPU 中介。适合大量数据传输（磁盘读写、网卡收发），CPU 只需发起 DMA 请求，数据传完后设备以中断通知 CPU。
